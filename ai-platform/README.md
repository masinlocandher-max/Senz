# SENZ AI Platform · six-product suite

This directory is an **independent Node 20+ application inside the canonical SENZ GitHub repository**. It does not replace GitHub Pages, alter the marketing website, or use Replit. The existing SENZ marketing site remains the public discovery surface; this application is the private paid-use surface.

## Product modules
| Product | First release workflow |
| --- | --- |
| AI Front Desk | FAQ records, inquiry handling, interactive assistant preview |
| AI Sales Desk | Lead records, pipeline stages, AI follow-up drafts |
| AI Knowledge Desk | Approved reference documents, source-grounded questions |
| AI Workspace | Saved work, role-specific AI assistance for licensed seats |
| AI Content Studio | Campaign briefs, draft generation, human approval statuses |
| AI Workflow Desk | Staff requests, approvals by authorized roles, AI summaries |

Shared capabilities: account sign-in, organization switcher, member invitations, white-label names/colors, product-by-product entitlement checks, PayMongo checkout, webhook-based activation, seat limits, usage records, CSV export and tenant-separated data.

## Strict implementation boundaries
- GitHub Pages cannot run protected APIs, charge cards or hold API secrets. Deploy this directory as a separate Node service (for example via a connected host pointing at this subdirectory).
- Do not expose the app as *ready for paid customers* until the database migration has been applied to a dedicated SENZ Supabase project, all keys are set in the host, PayMongo test and live webhook events are verified, AI costs are capped, and operational tests are completed.
- **Payment success redirect never grants access.** Only the verified PayMongo webhook activates a license in an atomic database transaction. Each protected operation validates the Supabase account, active organization membership, and active product license.
- An institution pays and grants seats to its members. Students and employees do **not** need to pay individually. A white-label license is a separate product from SENZ Partner Program membership; no membership fee silently includes a product license.
- Product prices are intentionally NOT hardcoded. The owner must supply approved prices in the private environment variable SENZ_PLAN_PRICING_JSON. Without prices the checkout is disabled.
- The first release does not send SMS/email, publish to social media, connect to Facebook/WhatsApp, autonomously approve staff requests, verify custom domains, or guarantee legal/compliance certification.
- AI responses are generated by the configured provider with explicit limits and human review. Automated billing renewal, refunds and cancellation flows require further commercial integration; this prototype uses clearly disclosed fixed-duration prepaid licenses.

## Start
1. Create a separate SENZ Supabase project and apply schema.sql there (do not apply to shared product databases).
2. Copy .env.example into host environment variables, never into committed source. Use an authenticated PayMongo test merchant and webhook secret. Set PUBLIC_APP_URL to the actual app origin.
3. Choose plan prices in pesos as a JSON object, e.g. a server-side mapping of plan IDs to approved numeric prices. Plans without approved prices remain quote-only.
4. Run \`node --test\` and \`npm start\` from this directory. Open the displayed local address.
5. Configure PayMongo webhook to POST \`/api/webhooks/paymongo\` with the \`checkout_session.payment.paid\` event. Confirm both successful and replayed deliveries in test mode.
6. Verify paid access, expired and suspended access, external tenant denial, seat limits, dashboard views, and one AI call in the live deployment before activating customer sales.

## API
GET /api/config, /api/catalog; GET /api/me, /api/entries, /api/usage; POST /api/checkout, /api/entries, /api/ai, /api/invites, /api/invites/redeem; PATCH /api/entries/:id, /api/organizations/:id, /api/memberships/:org/:user; POST /api/webhooks/paymongo.

All protected requests use \`Authorization: Bearer <Supabase access token>\`, never a service role key in the browser.

A 200 from /api/health proves only the Node process is alive, not successful payment or downstream integrations.

## Front Desk website integration
A paying Front Desk organization can allow five HTTPS origins and copy the widget script from License & Settings. The widget uses only approved FAQ records, collects opted-in inquiries, and limits AI replies per day. This does not include Facebook Messenger, WhatsApp, SMS, voice or autonomous follow-up. Configure CSP to permit the app host. Verify checkout and origin restrictions before enabling live traffic.

## Paid white-label reseller referral prototype
A reseller with an active white-label license may share an account-creation URL from its License & Settings screen. The linked organization can sign up and buy its own paid license. The buyer's private records, members, documents and AI usage remain in a separate organization; the reseller cannot read them. Orders are attributed to the reseller and aggregate gross referred sales appear in its dashboard. This is **not** an automated commission system, payment split, reseller merchant-of-record service, or a guarantee of margins. All product prices are controlled centrally in approved server configuration, and commissions must be defined separately.
